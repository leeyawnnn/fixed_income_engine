# Data

Two of the four files here are real market data with recorded provenance. One is
hand-written and labelled as such. Nothing in this directory is generated by a
model or a simulator.

Each downloaded CSV has a `.meta.json` sibling carrying the exact source URL,
the retrieval timestamp in UTC, the git commit of the fetching code, the row
count, the date span, and a SHA-256 of the file. Both CSVs also repeat the
source URL and the regeneration command in a comment header, so a file that
gets separated from this directory still says where it came from.

## What a CMT par yield actually is

Treasury's "Daily Treasury Par Yield Curve Rates" are **par yields**: the coupon
a hypothetical Treasury security would have to carry to trade at exactly 100 at
that maturity. Three consequences follow, and they matter for how the
bootstrapped curve in this repository should be read.

**They are derived, not observed.** Treasury takes bid-side yields on the
on-the-run securities from the Federal Reserve Bank of New York and fits a curve
through them, then reads the constant maturities off that fit. Since
**2021-12-06** the fit is a **monotone convex spline**; before that date it was a
quasi-cubic Hermite spline. So bootstrapping CMT rates recovers a zero curve
consistent with *Treasury's own interpolation of a handful of on-the-run
points*, not one implied by the full cross-section of outstanding bond prices.
A curve built from actual bond prices would disagree, most visibly wherever
individual issues trade special.

**They are par, not zero.** A 5-year par yield is not the 5-year zero rate. It
is the single coupon that makes a whole strip of semiannual payments worth par,
so reading it as a zero rate misprices every cashflow before maturity. That gap
is exactly what the bootstrap closes.

**The short end is a different animal.** The constant maturities at 1, 1.5, 2, 3,
4 and 6 months come from bills, which pay no coupon, and are quoted on a
coupon-equivalent basis rather than as coupon yields. This repository treats
every CMT point uniformly as a par instrument, which for the sub-6-month points
is a simplification; see the README's Limitations section.

The **1.5-month** series begins **2025-02-18**. Cells before that date are empty
in Treasury's file and are left empty here rather than filled or interpolated.

Rates are published at approximately 15:30 ET on US business days.

## Why there is no SOFR discount curve here

Post-2008 practice discounts collateralised cashflows on an OIS curve, so the
honest thing would be to build one. There is no free, redistributable USD SOFR
**swap** curve to build it from:

- FRED carries the **overnight fixing** (`SOFR`) and its backward-looking
  compounded averages (`SOFR30DAYAVG`, `SOFR90DAYAVG`, `SOFR180DAYAVG`,
  `SOFRINDEX`). All resolve, and the overnight series is committed here. None is
  a term structure: the averages describe a window that has already happened and
  say nothing about rates after today, so no forward-looking curve can be built
  from them.
- The ICE Swap Rate series FRED used to carry (`ICERATES1100USD*`) return **404**
  (checked 2026-09-18).
- **CME Term SOFR** is a licensed product and cannot be redistributed in this
  repository.

So discounting here is done on the bootstrapped Treasury curve. That is a
simplification, and it is a real one: a Treasury curve is not an OIS curve, and
the spread between them (the swap spread) is a traded quantity, not noise. For
scale, SOFR fixed at **3.87%** on 2025-12-31 against a 1-month CMT of
**3.74%** the same day. The engine supports the correct treatment — `Swap::pv`
takes separate discount and projection curves — so what is missing is the data,
not the capability.

## Verifying a file against its provenance record

```sh
python3 - <<'PY'
import hashlib, json, pathlib
for meta in sorted(pathlib.Path("data").glob("*.meta.json")):
    csv_path = meta.with_suffix("").with_suffix(".csv")
    recorded = json.loads(meta.read_text())["sha256"]
    actual = hashlib.sha256(csv_path.read_bytes()).hexdigest()
    print(f"{csv_path.name}: {'ok' if recorded == actual else 'MISMATCH'}")
PY
```
